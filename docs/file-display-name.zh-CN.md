## 1. 目标与术语

用户打开 `insight.jsonl` 后，可以把顶部文件标签改成「修改前」「追踪缺失」等便于自己辨认的名称。修改只发生在查看器的显示层，不改本地文件名，也不修改 JSONL 内容。

| 术语 | 含义 | 示例 |
| --- | --- | --- |
| 原文件名 | 导入文件时取得的名称，不受显示名称编辑影响 | `insight.jsonl` |
| 显示名称 | 标签当前呈现的名称；未设置别名时使用原文件名 | `追踪缺失` |
| 自定义别名 | 用户保存的显示名称，可清除以恢复原名 | `修改前` |
| 编辑草稿 | 正在输入但尚未保存的名称 | `修改前 · 测试环境` |
| 恢复按钮 | 仅在编辑状态出现的循环箭头图标按钮 | `↻`，实际使用图标组件 |

本功能不是文件系统重命名、日志内容编辑，也不是字段旁注功能。文件身份仍由内部文件 ID 决定，不能用显示名称识别文件。

## 2. 已确认的产品决策

### 2.1 已取代或不采用的方案

- 右击名称再通过菜单重命名，不作为本次主交互。
- 不增加常驻铅笔图标，也不在悬停时额外出现铅笔。
- 不在浮层中显示「显示名称：」「原文件名：」或「双击修改」等前缀和提示。
- 不增加文字形式的 `Reset` 按钮。
- 不在普通浏览状态为每个标签常驻恢复按钮。
- 不用浏览器原生 `title` 提示承担原名浮层，因为本方案需要主动控制位置，确保不覆盖当前名称。
- 不增加保存成功弹窗或通知；退出编辑、呈现新名称即是主要完成反馈。

## 4. 最终呈现效果

以下是结构示意，不是像素级设计稿。括号、分隔符和 `↻` 用于表达布局，实际视觉应沿用当前标签风格。

### 4.1 初始浏览

```text
[ insight.jsonl   2681   × ]
```

- 未设置别名时显示原文件名。
- 记录数和关闭按钮保持原有功能。
- 不出现输入框、恢复按钮或额外编辑图标。

### 4.2 悬停名称

假设标签已改名为「追踪缺失」：

```text
[ 追踪缺失   2681   × ]
    ↓ 与名称保留间距
  ┌─────────────────┐
  │ insight.jsonl   │
  └─────────────────┘
```

- 仅名称区域出现轻微背景反馈。
- 浮层中的可见文本只有 `insight.jsonl`。
- 标签仍显示「追踪缺失」，不被浮层替换或覆盖。
- `↓` 和「与名称保留间距」只用于本文解释，不是实际界面内容。

### 4.3 编辑状态

```text
[ [追踪缺失________]  ↻   2681   × ]
    名称输入框       恢复图标
```

- 输入框占据名称原有位置，保留标签本身。
- 进入时选择完整名称，即使浏览状态下该名称被省略。
- `↻` 表示类似用户示例中循环箭头的图标，不显示 `Reset` 字样。
- 记录数和关闭入口不因编辑而消失；精确间距可在实现中微调。
- 同一时间只允许一个标签编辑，避免同时存在多个草稿；编辑时隐藏原名浮层。

### 4.4 保存别名

```text
[ 修改前   2681   × ]
```

- 输入框和恢复按钮收起，新名称直接显示。
- 当前 JSON 详情、选中记录和搜索条件维持原状。
- 再次悬停时仍只显示 `insight.jsonl`。

### 4.5 恢复原名

```text
编辑中点击 ↻
        ↓
[ insight.jsonl   2681   × ]
```

- 清除自定义别名，退出编辑。
- 不弹确认框，不要求再按 Enter。
- 恢复按钮随编辑结束而消失。

## 5. 交互流程与状态转换

### 5.1 状态定义

| 状态 | 名称内容 | 输入框 | 恢复按钮 | 原名浮层 |
| --- | --- | --- | --- | --- |
| 浏览 | 已保存别名或原名 | 无 | 无 | 无 |
| 悬停 | 同浏览 | 无 | 无 | 只显示原名 |
| 编辑 | 当前草稿 | 有，进入时获得焦点 | 有 | 隐藏 |

### 5.2 事件处理表

| 事件 | 处理 | 结束后的状态 |
| --- | --- | --- |
| 鼠标进入名称区域 | 轻微背景变化，显示原名浮层 | 悬停 |
| 鼠标离开名称区域 | 关闭浮层，不改变已保存名称 | 浏览 |
| 双击名称 | 隐藏浮层，创建草稿，聚焦并全选 | 编辑 |
| 聚焦名称后按 F2 | 与双击名称使用同一个编辑流程，隐藏浮层、创建草稿、聚焦并全选 | 编辑 |
| 另一标签请求进入编辑 | 先保存并结束当前标签的编辑，再进入目标标签的编辑，不能同时保留两个编辑框 | 目标标签编辑 |
| 输入、删除、移动光标 | 仅更新草稿，不改日志和已保存别名 | 编辑 |
| Enter，且不处于输入法组合输入 | 按统一规则保存，退出编辑 | 浏览 |
| Esc，且不处于输入法组合输入 | 丢弃草稿，保留进入编辑前的名称 | 浏览 |
| 点击其他位置使输入框失焦 | 保存草稿，允许被点击控件继续执行原操作 | 浏览 |
| 点击恢复图标 | 恢复原文件名，不保存当前草稿；尚未设置别名时也结束编辑 | 浏览 |
| 点击关闭标签 | 关闭对应文件，清理编辑和浮层状态，不影响其他文件 | 该标签移除 |
| 切换到另一文件 | 保存原标签草稿后按原有规则切换 | 目标文件浏览 |

### 5.3 双击与普通切换的关系

- 名称区域才是双击编辑目标；记录数、空白区域和关闭按钮不触发编辑。
- 双击活动文件名称时，不能因为双击中的单击事件而清空选中记录。
- 双击非活动文件名称时，可先按原有规则切换文件，再进入编辑。
- 文件切换导致的正常选中记录变化，与活动文件上的改名操作应区分处理。
- 输入框内单击、双击选择文字、拖动选中文字，不得触发标签切换。

### 5.4 自动保存与恢复的优先级

恢复操作必须优先于普通失焦保存。

浏览器交互中，点击恢复按钮可能先让输入框失焦。如果失焦处理保存草稿，随后又覆盖恢复结果，就会出现「点击恢复却仍保留别名」的问题。

后续实现需要把保存、取消和恢复归入同一个结束编辑流程，确保每次编辑只提交一个最终结果：

1. 明确恢复操作：清除别名并结束编辑。
2. 明确取消操作：不提交草稿并结束编辑。
3. 普通保存操作：提交规范化草稿并结束编辑。

重复触发的 blur 或键盘事件不能再次提交已经结束的编辑会话。具体可以使用事件顺序控制或编辑状态保护，但不要求采用某一种实现方式。

### 5.5 输入法与焦点

- 中文等输入法组合输入期间，Enter 用于确认候选词，不得提前保存名称。
- 输入法仍在处理组合输入时，Esc 不应被应用强行解释为放弃整个编辑。
- Enter 或应用级 Esc 结束编辑后，建议把焦点返回同一标签的名称控件。
- 普通失焦保存不得把焦点抢回标签，否则会打断搜索框、设置或其他控件操作。
- 编辑时 Ctrl+A 应选择输入框中的名称，不应触发现有 JSON 内容全选逻辑。
- 编辑时上下箭头用于输入行为，不得触发日志记录导航。

## 6. 原文件名浮层设计

### 6.1 内容约束

- 可见文本只能是原文件名本身。
- 不显示别名，不添加解释性前缀、双击提示或其他操作文字。
- 浮层不包含按钮、输入框、菜单等交互控件。
- 不把名称作为 HTML 解释；特殊字符按普通文本呈现。

### 6.2 位置与边界

- 浮层以名称区域为锚点，优先位于下方，建议间距为 6～8px。
- 下方空间不足时放到上方，同样与标签保持间距。
- 水平方向根据视口边界调整，不应溢出屏幕左右边缘。
- 原文件名很长时限制浮层宽度并允许换行，不只展示截断片段。
- 浮层不能因增加到标签 DOM 中而改变标签高度、宽度或记录区布局。
- 现有标签栏使用横向滚动及 overflow；需要防止浮层被标签栏裁切，可使用独立浮层容器或等价方案。
- 若特殊小视口中上下均不足，可限制高度并调整位置；不能通过覆盖名称来解决。

### 6.3 显示生命周期

- 鼠标离开名称、进入编辑、关闭文件时关闭浮层。
- 标签栏滚动或页面尺寸变化时，重新定位或关闭后等待再次悬停，不能停留在错误位置。
- 原名浮层不接管鼠标操作，避免遮挡其他控件的点击。
- 可考虑对名称键盘聚焦提供相同原名信息；这是可访问性补充建议，不增加可见提示文案。
- 不同时使用另一套包含额外文字的原生 `title` 提示，避免出现两层浮层。

## 7. 名称数据与保存边界

### 7.1 数据模型建议

保留当前 `name` 作为原文件名，追加独立属性，例如：

```ts
interface FileData {
  id: string;
  name: string;
  displayName?: string;
  lines: JsonLine[];
  filter: string;
  sortOrder: "asc" | "desc";
}
```

以上为类型示意；实际实现已在 `src/app/page.tsx` 的 `FileData` 中追加可选 `displayName`，原 `name` 保持不变。

- 最终展示取自有效 `displayName`，否则使用 `name`。
- 输入框使用独立草稿状态，不能在每次敲键时覆盖原文件名。
- 编辑状态必须绑定文件 ID，不能绑定标签数组位置。
- 文件 ID、记录数据和每文件搜索／排序配置均保持不变。
- 保存与原文件名相同的名称时，建议直接清除别名，避免多种「恢复原名」状态。
- 清除别名就是恢复原名，不需要读取磁盘或重新解析日志。

### 7.2 名称规则与补充建议

以下规则已确认，与第 2.2 节保持一致：

- 去除首尾空白，但不擅自删除用户名称内部空格。
- 空值或仅空白名称恢复原名，不保留不可见的空标签。
- 允许相同别名，不静默追加序号，也不按别名合并标签。
- 短名称在浏览时按内容自适应宽度；长名称只在浏览展示时省略，保存和编辑时均保留完整内容。

以下为补充输入建议，尚未在本次边界确认中逐项确定：

- 允许中文、英文、数字、空格、标点和 Emoji；不强制保留 `.jsonl` 后缀。
- 不限制为操作系统文件名字符，因为本功能不创建磁盘文件。
- 暂不设业务字符上限；具体限制如需引入，应另行确认，不能因标签展示宽度擅自截断保存内容。
- 对粘贴进名称框的换行等输入应有一致处理；建议保持单行名称，不引入多行标签。

### 7.3 已确认的会话保存策略

首版仅把别名保存在当前页面内存状态中，不做跨会话恢复：

- 关闭设置、切换模式、切换文件后仍保留别名。
- 刷新页面、关闭标签后重新导入或新开页面时，使用原文件名。
- 不使用文件名推断跨会话身份，不写入文件，不上传到服务端。
- 不因其他偏好使用 `localStorage`，就宣称文件别名也已经持久化。
- 若后续需要长期保存，应单独设计文件身份和恢复机制。

## 8. 样式、安全与可访问性

### 8.1 样式

- 沿用当前标签高度、圆角、文字大小和活动态边框。
- 悬停背景变化只作用于名称区域，不能覆盖活动文件识别状态。
- 输入框有清晰但轻量的边框，宽度随名称适度调整并设上限。
- 恢复图标与输入框垂直对齐，采用循环箭头轮廓，不使用文字标签。
- 实际点击区域应大于图标笔画范围，避免小图标难以点击。
- 深色、浅色和暖色主题下，输入文字、背景、焦点及图标均应可辨认。
- 标签栏仍可横向滚动，不挤压主要日志阅读区。

### 8.2 安全与可访问性

- 用户名称和原文件名作为文本渲染，不执行 HTML、脚本或模板表达式。
- 输入框提供无障碍名称；恢复图标提供「恢复原文件名」的屏幕阅读器名称。
- 无障碍名称不等于新增可见文字，不违背只显示图标的视觉要求。
- 名称控件、输入框、恢复和关闭按钮应有可见键盘焦点。
- 不把输入框或恢复按钮嵌套到另一个原生按钮中。
- 关闭按钮保留独立行为，不能因事件冒泡进入名称编辑。
- 支持聚焦名称后按 F2 进入编辑，与双击使用同一个流程；不能把鼠标双击称为已经覆盖纯键盘操作。
- 移动端双击、长按或额外入口本轮未确认，不纳入已承诺交互。

## 9. 与现有功能的兼容要求

改名、取消和恢复均应满足：

- 不重新执行文件读取和 JSONL 解析。
- 不修改 Raw 内容、Pretty 格式化结果或 Tree 数据结构。
- 不改变复制按钮输出。
- 不清空当前活动文件的关键词或正序／倒序状态。
- 不清空该文件当前选中记录、详情模式、活动搜索匹配和 Tree 手动展开状态。
- 不改变记录 ID、记录数、字节大小和虚拟列表数据身份。
- 不串改其他文件的原名或显示名称。
- 不因名称变长影响列表和详情区布局。

输入框接管文字输入相关键盘行为，但不改变未编辑时既有记录导航规则。文件正常切换仍遵循原有行为；本功能不承诺新增每文件独立的选中记录恢复能力。
